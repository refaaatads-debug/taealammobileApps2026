أريد منك حل مشكلة الاتصال الحالية بشكل نهائي ومنهجي، وليس تجربة تعديلات عشوائية على الكود.

المشكلة الحالية:

التطبيق Expo يحصل على Supabase Bearer Token بشكل صحيح، ثم يرسل الطلب إلى API الموجود حالياً داخل Replit.

التدفق:

Expo
↓
Supabase Auth
↓
Bearer Token
↓
Replit API
↓
محاولة التحقق من المستخدم عبر Supabase
↓
فشل اتصال الشبكة
↓
401 / "تعذر التحقق من الحساب"

الأدلة الحالية تشير إلى أن المشكلة ليست في:
- شاشة Login
- SecureStore
- Bearer Token
- Supabase Auth
- Supabase URL
- Publishable Key
- RLS
- Database credentials

المشكلة الأساسية المشتبه بها هي Network Connectivity من بيئة Replit إلى الـVPS/Supabase.

المعلومات التي ثبتت سابقاً:

VPS IP:
72.61.23.237

Replit outbound IP الذي ظهر أثناء الفحص:
34.180.8.129

الاتصالات من Replit إلى VPS فشلت بـ TCP TIMEOUT على:
- 22 SSH
- 80 HTTP
- 443 HTTPS
- 8000 HTTP

بينما من داخل الـVPS:
- Nginx يعمل.
- 80 و443 عليهما listeners.
- HTTPS للدومين يعمل محلياً.
- /api/healthz يعمل.
- Firewall/UFW يحتويان على السماح لـ443.

كما أن PostgreSQL الموجود عبر DATABASE_URL يستخدم:
hostname = helium
database = heliumdb

ولا أريد منك افتراض أن heliumdb هو Supabase أو أنه بديل عنه؛ تحقق من العلاقة الفعلية أولاً.
