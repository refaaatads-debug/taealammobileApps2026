نعم. **الآن أنت في أفضل مرحلة للتنفيذ**: طالما لديك المخطط الهندسي الكامل للمنصة الأصلية + الكود + قاعدة البيانات، يمكن جعل لوحة المعلم في التطبيق مطابقة للمنصة بدل التخمين.

أهم شيء: **لا نسمح لـ Replit Agent بتعديل المنصة الأصلية أثناء المطابقة.**

استخدم له هذا البرومبت:

> **نفّذ الآن مطابقة لوحة تحكم المعلم في تطبيق الهاتف مع المنصة الأصلية اعتماداً على المخطط الهندسي والكود وقاعدة البيانات المرفقة كمصدر حقيقة وحيد.**
>
> ### قواعد إلزامية
>
> * **ممنوع منعاً باتاً تعديل أو حذف أو إضافة أي شيء في كود المنصة الرئيسية.**
> * **ممنوع تعديل VPS أو Docker أو Nginx أو Kong أو Supabase Auth/OAuth.**
> * **ممنوع تعديل Production Database أو Schema أو RLS أو RPC أو Functions أو Triggers أو Policies.**
> * **ممنوع إنشاء جداول أو بيانات بديلة أو Mock Data للتعويض عن أي نقص.**
> * **ممنوع تغيير أي خاصية أو سلوك موجود في المنصة الأصلية.**
> * التطبيق فقط هو المسموح تعديله.
>
> ### المطلوب
>
> استخدم المخطط والكود الأصلي لتحديد ومطابقة لوحة المعلم بالكامل:
>
> `Auth → Role → Profile → Dashboard → Teachers/Students → Requests → Bookings → Schedule → Availability → Sessions → Calls → Earnings → Wallet → Subscriptions → Invoices → Notifications → Messages → Settings → Reports`
>
> لكل قسم:
>
> 1. حدد الصفحة والمسار الأصلي.
> 2. حدد مصدر البيانات والجداول المستخدمة.
> 3. حدد API/RPC/Function المستخدمة.
> 4. حدد شروط الصلاحيات وRLS.
> 5. حدد حالات البيانات والانتقالات بينها.
> 6. حدد الأحداث والإشعارات الناتجة.
> 7. طابقها في تطبيق الهاتف **بالسلوك نفسه وليس الشكل فقط**.
> 8. استخدم نفس Production Data ونفس العلاقات والمنطق الأصلي.
>
> ### الهوية
>
> يجب أن يكون:
>
> `Supabase Auth user.id`
> → `profiles.user_id`
> → `user_roles.user_id`
> → نفس المعلم الموجود في المنصة الأصلية
>
> لا تستخدم قاعدة محلية بديلة للهوية أو الدور أو بيانات المعلم.
>
> ### عند وجود اختلاف
>
> لا تخمّن ولا تنشئ حلاً جديداً.
>
> سجّل:
>
> * ما هو موجود في المنصة.
> * ما هو موجود في التطبيق.
> * الفرق.
> * سبب الفرق.
> * التعديل المطلوب في **التطبيق فقط**.
>
> ### الاختبارات
>
> نفّذ أولاً اختبارات قراءة ومقارنة فقط.
>
> لا تنفذ أي عملية مالية أو حجز أو تعديل Production إلا بعد وجود اختبار مصرح به صراحة.
>
> في النهاية أعطني تقريراً مختصراً:
>
> **مطابق ✅ / مختلف ⚠️ / غير مثبت ❓**
>
> لكل قسم من لوحة المعلم، مع قائمة دقيقة بما تم تعديله في التطبيق فقط.
>
> **أهم شرط: أي أمر قد يؤدي إلى تغيير المنصة الرئيسية أو قاعدة بيانات Production أو خصائصها يجب إيقافه فوراً وعدم تنفيذه.**
