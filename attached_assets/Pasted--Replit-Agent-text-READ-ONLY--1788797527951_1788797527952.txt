```text
أريد منك إجراء تحليل READ-ONLY فقط، بدون تعديل أي ملف أو كود أو Secret أو Environment Variable أو قاعدة بيانات.

هدفي أن أفهم بدقة كيف التطبيق الحالي متصل بقاعدة البيانات وSupabase.

افحص المشروع بالكامل وحدد مسار الاتصال الحقيقي من التطبيق حتى قاعدة البيانات، ولا تفترض أي شيء.

أريد تقريرًا واضحًا يجيب تحديدًا عن الآتي:

1. تطبيق Expo/React Native:
   - هل يتصل مباشرة بـ Supabase؟
   - أم يتصل بـ API موجود على Replit؟
   - أم يتصل بـ VPS؟
   - حدد الملفات والأسطر التي تثبت ذلك.

2. API:
   - ما هو عنوان الـ API المستخدم فعليًا؟
   - ما هي الـ endpoints الخاصة بتسجيل الدخول وجلب بيانات المستخدم؟
   - هل /api/me يتصل بـ Supabase؟
   - كيف يتم تمرير Access Token / Bearer Token؟

3. Supabase:
   - ما هو عنوان Supabase المستخدم فعليًا؟
   - هل الاتصال يتم عبر Supabase Auth REST API أم SDK أم PostgREST؟
   - كيف يتم التحقق من المستخدم؟
   - كيف يتم جلب Profile بعد تسجيل الدخول؟

4. قاعدة البيانات:
   - هل التطبيق يتصل بقاعدة PostgreSQL مباشرة؟
   - أم أن الاتصال يتم فقط من خلال Supabase؟
   - حدد أين توجد بيانات الاتصال إن وجدت، بدون إظهار أي Secret أو Password أو Service Role Key.

5. VPS:
   - ما الدور الحقيقي للـ VPS؟
   - هل يستضيف Supabase؟
   - هل يستضيف API؟
   - هل Nginx يعمل كـ reverse proxy؟
   - ارسم مسار الاتصال الحالي.

6. أريد مخططًا نصيًا واضحًا بهذا الشكل بعد تصحيحه حسب المشروع:

Expo App
   ↓
؟
   ↓
؟
   ↓
Supabase Auth
   ↓
PostgreSQL

7. حدد أيضًا:
   - ما الذي يحدث عند Login خطوة بخطوة.
   - أين يحدث الفشل إذا تعذر VPS أو Supabase.
   - لماذا التطبيق يعمل أحيانًا ولا يعمل أحيانًا إذا كان ذلك ظاهرًا من الكود.

8. مهم جدًا:
   لا تغيّر أي شيء.
   لا تصلح أي شيء.
   لا تنشئ ملفات.
   لا تغيّر Secrets.
   لا تعمل Deploy.
   فقط افحص واكتب تقريرًا.

في النهاية أعطني:
A) Architecture الحالية
B) مسار Login الكامل
C) طريقة اتصال قاعدة البيانات
D) دور Replit
E) دور VPS
F) دور Supabase
G) الملفات الرئيسية التي تثبت كل نقطة
H) خلاصة قصيرة جدًا: "التطبيق متصل بقاعدة البيانات عن طريق ______".
```
