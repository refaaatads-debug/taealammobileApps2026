نريد الوصول إلى هدفك الأساسي:

أي طالب أو معلم يستخدم التطبيق يجب أن يرى ويستخدم نفس الحساب والبيانات والصلاحيات والعمليات الموجودة في المنصة، بدون إنشاء نظام بديل.

نفّذ مع Replit Agent بهذا الترتيب:

تثبيت اتصال التطبيق بـ Supabase Production فقط.
مطابقة هوية المستخدم:
نفس auth.users
نفس profiles
نفس user_roles
نفس صلاحيات الطالب/المعلم.
لوحة الطالب مطابقة للمنصة:
البيانات الشخصية
المعلمين
المواد
الحجوزات
الجلسات
الباقات والرصيد
الفواتير
المحفظة
الإشعارات
المحادثات.
دورة الحجز كاملة:
طالب → اختيار المعلم → الموعد → booking_request → قبول المعلم → حجز مؤكد → جلسة → إنهاء → الخصم/التعويض.
لوحة المعلم بنفس المنطق والبيانات.
Realtime والتزامن حتى يظهر التغيير في التطبيق والمنصة والعكس.
اختبار كل عملية قراءة أولاً، ثم العمليات الكتابية بحسابات اختبار حقيقية فقط، مع منع أي تغيير في Schema أو جداول Production.
وهذا هو البرومبت الذي أنصح بإرساله الآن:

نعود الآن للعمل على تطبيق الهاتف فقط.

أريد جعل التطبيق مطابقاً للمنصة الأصلية وظيفياً وبياناتياً، وليس بناء نظام بديل.

المنصة الأصلية + Supabase Production هما مصدر الحقيقة الوحيد.

ممنوع تعديل المنصة الأصلية أو Production بأي شكل.

لا تغيّر Schema أو Tables أو RLS أو RPC أو Functions أو Triggers أو Auth أو OAuth أو Nginx أو VPS.

في التطبيق:

استخدم نفس جداول وRPC وAPI والمنطق الموجود في المنصة الأصلية.
لا تنشئ جداول بديلة أو بيانات تجريبية.
لا تنشئ منطق حجز أو اشتراك مختلف عن المنصة.
نفس المستخدم في المنصة يجب أن يكون نفس المستخدم في التطبيق.
نفس Role والصلاحيات والبيانات.

ابدأ الآن بالتدقيق فقط في تطبيق الهاتف وقارنه بالمنصة الأصلية، ثم نفّذ المطابقة تدريجياً:

Auth → Student Dashboard → Teachers → Subjects → Packages/Subscriptions → Booking Request → Teacher Accept/Reject → Confirmed Booking → Sessions → Wallet → Invoices → Notifications → Chat → Calls.

لكل قسم:

حدد كيف تعمل العملية في المنصة الأصلية.
حدد كيف يعمل التطبيق حالياً.
حدد الفرق.
أصلح الفرق داخل التطبيق فقط.
اختبر TypeScript/Build/API.

ممنوع إجراء أي تعديل على Production أثناء هذه المرحلة.

لا تعتبر أي قسم مكتملاً إلا بعد التأكد أن التطبيق يستخدم نفس مصدر البيانات والمنطق والحالات والصلاحيات الموجودة في المنصة الأصلية.

ابدأ أولاً بـ هوية المستخدم والـRoles ثم لوحة الطالب والحجز، لأن الحجز هو أهم عملية يجب أن تتطابق بالكامل.

عند وجود أي شيء غير واضح في المنصة الأصلية، توقف واسأل ولا تخمّن.

باختصار: لا نحتاج الآن لإضافة ميزات عشوائية. نحتاج أن نجعل التطبيق واجهة أخرى لنفس المنصة ونفس الحساب ونفس البيانات ونفس العمليات.
