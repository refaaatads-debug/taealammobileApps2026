---
name: Expo static Preview isolation
description: The resource-safe relationship between Expo bundle generation and the artifact Preview server.
---

The Preview service must listen on its assigned artifact port while any temporary Metro process used to generate Expo bundles listens on a separate internal port. A Preview port exposed during generation can receive browser/mobile bundle requests before the build is complete, creating concurrent iOS, Android, and Web bundling and exhausting the Workspace. For this Expo Web artifact, start the static server immediately, build into an isolated staging directory, and atomically swap the completed directory into place; never run `expo export --clear` against the directory currently being served.

**Why:** A mobile Preview attempt became unstable when the build process reused the public service port; the Preview connected to Metro mid-build and the Workspace repeatedly restarted. Separating the ports allowed bundle generation and the static server to be tested independently. Later, the remote Preview repeatedly requested the Metro Web entry bundle and relaunched the app without any source changes; disabling dev mode did not prevent it, while a static export stopped the loop. A subsequent `--clear` of the live output directory produced `503` responses and white screens during each rebuild, so staging plus an atomic swap is required.

**How to apply:** Keep `/status` on the stable static server port. Use a distinct internal `EXPO_BUILD_PORT` for one-off Metro work, and do not make the artifact Workflow wait on a long-running Metro process when a static Expo manifest/bundle server is the intended Preview path. For a development proxy that must stay in front of Metro, `/status` must probe Metro before returning 200, and the proxy must exit when Metro exits instead of serving a permanent upstream-refused page. For Web Preview, keep the last good output available while exporting into a staging directory, then swap the directories only after `index.html` exists; serve both the artifact root and configured base path, and return the SPA shell for deep links. When diagnosing repeated API bootstrap calls, identify the User-Agent first: Replit's host, workspace iframe, and screenshot/browser clients can each load the same Preview independently.
